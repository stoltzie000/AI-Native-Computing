# AI-Native-Computing
Research and development of a next-generation AI-native computing architecture, including purpose-built processors, memory systems, motherboard design, interconnects, and software, engineered from first principles to outperform conventional GPU-based AI computing.

## Engineering status (2026-11-23)

The first reproducible research simulator is available at [simulator_v0_2](simulator_v0_2/README.md). It models fast/bulk memory traffic, KV-cache movement, compute ceilings, capacity, multi-node fabric overhead, and a simple physical SRAM area limit. An isolated local run passed **21/21 tests**. A GitHub Actions regression workflow is configured but its execution status is not yet confirmed.

**No superior physical AI processor has been demonstrated.** The optimistic SRAM-based candidate requires wafer-scale or multi-chiplet integration and real electrical/thermal verification. Simulated scenario throughput must not be interpreted as measured hardware performance.

See [product definition](docs/PRODUCT_DEFINITION.md), [validation protocol](docs/VALIDATION_PLAN.md), [project state](PROJECT_STATE.md), and [physical feasibility screen](simulator_v0_2/docs/PHYSICAL_FEASIBILITY_SCREEN.md).

## Equal-resource & algorithmic feasibility correction — v0.5 (2026-11-23)

[**Simulator v0.5 and tested source**](simulator_v0_5/README.md) · [Physical baseline evidence](simulator_v0_5/docs/PHYSICAL_AND_BASELINE_SOURCES.md) · [Design rejection ledger](simulator_v0_5/docs/DECISION_LEDGER.md) · [Next experiments](simulator_v0_5/docs/RESEARCH_ROADMAP.md) · [Deterministic results](simulator_v0_5/results/summary.json).

**Critical baseline correction:** NVIDIA Rubin now advertises 288GB HBM4 at 22 TB/s, comparable in memory class to our previous eight-stack hypothetical 288GB/22.4TB/s design. The nominal HBM configuration alone does not establish GPU superiority. In an E1 equal-memory/compute experiment, **one idealized shared domain modeled ~569.70 outputs/s, two packages ~557.74, and the eight-package mesh ~507.99**. These are synthetic resource models, not measured throughput or actual Rubin benchmarks.

**Algorithmic experiment:** Lossless skipping of three of four exact-zero blocks in a constructed 16x16 matrix passed independent numerical checks and stored toy weight data plus metadata in 261B vs 1024B (74.51% reduction); **this does not establish real AI model sparsity, equal model quality or superior hardware performance**.

The package passed **70/70 local tests**, and the complete historical v0.2–v0.5 suites passed **158/158 tests** after clean ZIP extraction. GitHub v0.5 source and results were fetched back and matched exact local Git blob hashes. No silicon, custom PCB, physical power measurement, or complete AI model performance test has been completed.

## Hardware-executable sparse PE candidate — v0.6 (2026-11-23)

[RTL candidate and testbench](prototype_v0_6/README.md) · [Verilog source](prototype_v0_6/rtl/block_sparse_pe.v) · [Verification plan](prototype_v0_6/docs/VERIFICATION.md) · [GitHub Actions RTL workflow](.github/workflows/sparse-rtl-tests.yml).

A minimal 4×4 signed INT8 matrix-vector processing element is authored in Verilog. It can skip externally certified all-zero weight blocks and counts multiplication cycles. An independent Python reference passed **11/11 tests**, bringing the historical v0.2–v0.6 Python suite to **169/169 locally passed tests**. The full package was also extracted into a clean directory and all Python tests passed there. **Actual Verilog compilation/simulation and FPGA/ASIC implementation have NOT been verified** in this session because no local HDL simulator was installed and no successful remote Actions run was observed. This kernel is not a complete AI processor or a proven GPU competitor.

## Verified RTL and trained-checkpoint audit — v0.7 to v0.9 (2026-11-23)

- [v0.7 input-latched multi-lane block-sparse PE](prototype_v0_7/README.md) — Icarus Verilog passes 256 v0.6 compatibility plus 1320 v0.7 random/deterministic cases; generic Yosys synthesis and ten-configuration cell sweep verified. The original v0.6 syntax defect was documented, not hidden.
- [v0.8 exact-zero activation-gated per-weight requests](prototype_v0_8/README.md) — real RTL testbench counted skipped external requests; 198 RTL cases and 14 Python tests passed, generic Yosys synthesis complete.
- [v0.9 coalesced column-major weight fetch](prototype_v0_9/README.md) — 264 RTL cases, 15 Python tests, Yosys 5370 generic cells passed; physical burst granularity model motivates wider tile/SRAM buffer.
- [Real pretrained checkpoint zero-block audit](experiments/real_weight_audit/README.md) — two genuine pretrained weight files independently SHA256-verified and audited in successful GitHub Actions. **Zero exact-zero 4x4 or 8x8 blocks measured in both**. [Committed aggregate results](experiments/real_weight_audit/results/MEASURED_2026-11-23.json) and [scientific decision](experiments/real_weight_audit/RESEARCH_DECISION.md).

**Current engineering conclusion:** Unpruned weight-zero-block bypass cannot accelerate the two actual audited checkpoints. Activation-zero rates in real models, realistic memory-burst/queue behavior, device clock/power, complete AI-task quality and GPU-comparable performance remain unmeasured. No new physical processor, custom motherboard or demonstrated superior AI computer exists yet. [PROJECT_STATE.md](PROJECT_STATE.md) is the canonical continuation record. The priority is rigorous full-system co-design, not just incremental toy MAC pipelines.
