# Communication interruption recovery protocol v1
Status: adopted for engineering workflow; not a platform timeout fix.
Before any mutation: read current branch SHA, intended paths and relevant run history. Record operation identity (branch, expected parent, intended content or commit SHA, workflow, event). Use non-force expected-parent updates. After ambiguous response, inspect remote head, ancestry and content; if intended change exists, verify and do not submit again. If head changed unexpectedly, reconcile, never overwrite. For CI use one push trigger per engineering change, identify run by head SHA/workflow/event, inspect attempts and job logs before any retry. No blind dispatch or rerun; if discovery is inconclusive, preserve pending state and perform independent work. A successful API response is not proof of test success.
Emit substantive progress at each bounded unit, target <=20s when possible and <=60s when execution permits; no guaranteed transport heartbeat during blocking calls. Prefer scoped reads and small atomic commits, no long synchronous wait for CI. Continue independent work; checkpoint is not an approval gate. Documentation-only checkpoints must not trigger engineering workflows unnecessarily.
Record each observed session start/end, workload class, elapsed observation time, client-visible delivery outcome (success/timeout/unknown), incident timestamp, last visible update, operation identity and recovery outcome. Do not infer timeout from an assistant turn ending. Compare timeout count / observed comparable sessions and exposure hours, with unknown outcomes separate. No historical denominator available; baseline frequency UNKNOWN. This session cannot observe client receipt or internal server logs. Do not publish HAR, cookies, credentials or private conversation URLs in this public repository. Official guidance: https://help.openai.com/en/articles/7996703-troubleshooting-chatgpt-error-messages ; https://status.openai.com/ . The 180-second threshold is unverified. No permissions changes.
